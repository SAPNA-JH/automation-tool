How to introduce this project in an interview

“PostPilot is a full-stack AI content automation platform for Instagram. I built it to reduce the repetitive work behind consistent social media publishing. A user selects a niche or topic, and the backend generates structured content, branded visual posts, captions, hashtags, and optionally short Reels. The React dashboard keeps a human in the loop for review, editing, regeneration, and approval. For publishing, it uses Google sign-in, per-user data isolation, encrypted Instagram credentials, Cloudinary-hosted media, and the official Instagram API. The main engineering challenge was making generative output reliable, so I used provider fallbacks, structured JSON validation, template-based rendering, background jobs, and rate limits rather than relying on a single model response.”

AI implementation

What actually happens when someone clicks “Generate”

This is the strongest technical story for positioning the project as real AI engineering rather than a simple API wrapper.

Pick context

The app selects a user-defined category and template, or uses weighted content pillars. The user can also provide an exact theme.

Build a structured brief

Brand voice, niche, visual style, accent color, category, and theme are passed to an LLM prompt so the output stays relevant to the user’s account.

Validate generated content

For infographic and Reel formats, the app asks for JSON, extracts it defensively, and falls back to deterministic content if the provider fails or returns incomplete data.

Render the media

Pillow composes image templates; the Reel pipeline uses generated scripts, Edge TTS narration, word timings, ffmpeg transitions, captions, and music.

Review and publish

A background job saves the pending asset. The user reviews it in the dashboard, then can approve it for a manual or automated official Instagram publish.

Provider resilience

The app can route between Gemini, Anthropic, OpenAI, and Cloudflare Workers AI, with template or generated-placeholder fallback paths. This helps the product remain useful when a key is missing, a provider fails, or an API response is malformed.

Reliable output over “pure AI”

AI produces the ideas and structured content, while deterministic templates create readable branded assets. That division avoids depending on image models to render accurate text inside every social graphic.

Safe resource usage

Generation runs in background threads behind a configurable semaphore. Video rendering checks available memory and can degrade to an image post instead of crashing a small deployment.

Interview practice

Questions you are likely to get

Keep answers conversational. Start with the bold first sentence, then go deeper only if the interviewer is interested.

Why did you use a multi-provider AI design?

To make content generation dependable instead of coupling the product to one vendor. Different providers can be selected by configuration, and the app includes fallback content or placeholders. This gives a smoother user experience during an outage or when a developer is working without paid API keys.

How do you avoid bad LLM output breaking the UI?

I treat LLM output as untrusted input. The backend prompts for strict JSON where structure matters, extracts and sanitizes it, limits list lengths, and checks that required fields exist. If validation fails, it falls back rather than sending malformed data to the renderer.

Why is generation asynchronous?

Media creation is expensive and should not make a web request time out. Image and especially video rendering can use substantial CPU and memory, so the API creates a job, processes it in the background, and lets the frontend poll job state while the user continues working.

How did you protect user data?

Every API path is authenticated and data queries are scoped to the current user. The backend uses Google sign-in and JWTs, stores Instagram secrets and tokens encrypted at rest, validates OAuth state, and disables unsafe development settings in production.

What was the hardest engineering trade-off?

Making automated visuals reliable while retaining the creative benefit of AI. I used LLMs for ideas, captions, scripts, and structured copy, then rendered text-heavy graphics with code-driven templates. This makes typography and branding consistent while still letting AI drive the content.

What would you improve next?

I would move in-process jobs to a durable queue such as Celery or RQ with Redis, add automated tests and observability around providers, and use object storage plus signed URLs. I would also add a content calendar, analytics feedback loop, and stronger moderation before automated publishing.

Technical decisions

Details that demonstrate engineering depth

Data portability

The data layer supports local SQLite for simple development and PostgreSQL through psycopg for deployment. It also stores user accounts, posts, settings, niche presets, automation state, and Instagram connection state.

Correct publishing architecture

Instagram needs a publicly accessible media URL. The project supports Cloudinary storage so generated media survives redeploys and can be fetched by Meta when publishing.

Production safeguards

The app validates production configuration at startup, rate-limits generation, serializes memory-heavy work, verifies Instagram token freshness, and uses an externally triggerable cron endpoint for hosts that sleep.

Custom content system

It is not limited to one template: the project has post and Reel registries, niche presets, weighted categories, editable brand settings, generated preview assets, and multiple creative layouts.

Video composition

The Reel pipeline generates narration with Edge TTS, tracks word timestamps, draws caption overlays with Pillow, and assembles the final vertical video through ffmpeg.

Deployment separation

The frontend is a static Vite build designed for Vercel, while the FastAPI service has a Dockerfile with ffmpeg installed. This separates UI delivery from the server-side media workload.
